# GamePilot：自有 Godot 射击游戏的自动试玩 Agent

状态：用户已确认，按里程碑实现。2026-10-18。

## 目标和选择

采用 Godot RL Agents 路线，接入 `Huhuhuc/2dshootgame`，创建独立 GamePilot 工作目录。原游戏资源、移动、子弹、碰撞、敌人、Buff 与结算规则应复用，不另写一个 Python 玩具环境冒充原游戏。保持原项目可玩，不直接覆盖其主分支。

最终演示：训练后的策略在真实 Godot 游戏内移动、避敌、射击，在固定测试种子下与随机策略及规则 Bot 比较，并导出逐局指标和失败轨迹。第一版定位为 RL 试玩与难度评测，不声称通用游戏 Agent、漏洞自动定位或大模型算法创新。

## 技术与模块

- 游戏：Godot 4.6.1，原 2D 射击项目，物理步长 1/60 秒。
- 桥接：复用并固定 Godot RL Agents 的 Python/插件版本，核对协议 0.7；在独立适配层明确 seed、reset、terminated/truncated、超时和生命周期。
- 训练：独立 Python 3.12 虚拟环境，Stable-Baselines3 PPO、小型 MLP，先 CPU 测速。依赖完成安装与验证后冻结版本。
- 推理：Python 加载保存策略，通过同一桥接运行；第一版不依赖 Godot .NET/ONNX。
- 评测：JSON/CSV 逐局记录，静态 HTML 报告或图表。使用暖灰、墨黑、橙色，不用蓝色主题。

## 观测与动作初版

每 4 个物理帧决策一次，动作重复期间仍使用原游戏的物理更新；训练和推理保持相同 action_repeat。

观测由适配器显式读取游戏状态，不读屏幕：

- 玩家归一化位置、速度、生命、无敌剩余时间、射击冷却、局内剩余时间。
- 最近 6 个敌人的相对位置、相对速度、生命、类型及存在标记，稳定按距离与出生序号排序；不足补零。
- 最近 2 个道具的相对位置、类型与存在标记。
- 8 个方向的墙体距离，避免仅依赖世界坐标判断障碍。
- Buff/形态状态。所有输入定义范围，检查有限值，不能把未来刷新位置或随机数状态给策略。

动作采用两个离散分量：移动 9 种（静止＋八方向）、射击 9 种（不射击＋八方向）。使用 MultiDiscrete([9,9]) 并先验证上游转换和 SB3 兼容性。若需要定制映射，保留索引表和对应测试。规则 Bot、随机 Bot 与 PPO 共用动作定义。

## 回合与随机性

- 自然终止：玩家死亡，或到达原游戏 60 秒通关时间；时间是可观测任务条件，因此该通关属于任务完成。
- 外部测试限步属于 truncated；连接错误标为运行失败，不计为通关或正常游戏失败。
- 末状态、末奖励和结果先返回，再由环境 reset；禁止静默自动跳过末状态。
- reset 清理敌人、子弹、掉落、Buff、计时器、动画状态、暂停标志、速度、生命及事件累计量。
- 分离刷新、掉落等随机流。保存主 seed、局号、配置哈希、版本、逐步动作；先验证同版本同动作的重复运行，再承诺可复现范围。跨系统浮点/物理完全一致不作保证。

## 奖励与训练

第一轮冻结奖励 v1：存活每游戏秒 +0.02，独立击杀每个 +0.2，实际损失每点生命 -0.5，死亡 -2，通关 +2。按事件统计，不能每次读取重复奖励；同一敌人仅计一次击杀。连锁爆炸归因规则要明确，第一版以局内死亡事件计数，不虚称全部为直接射杀。

这些权重是待实验的起点，不保证最优。评测以通关率、存活时间、受伤、击杀等真实指标为主，不以累计奖励提高冒充能力提高。

课程：先单类普通敌人和较低刷新压力检查学习，再训练原四类敌人混合场景。每个课程配置独立记录；最终测试回到原版完整配置，不能只展示简单课程结果。

先做 10,000 步训练连通性验证；确认环境每秒样本数与终止统计后，再做 100,000 步初版。若效果不足，保留结果再决定扩充预算，不后台无限训练。保存最后模型、验证集最佳模型、配置和日志。

## 基线与评测

- 随机策略：对相同动作空间采样，不拥有额外信息。
- 规则策略：根据同一观测躲避近敌、避免靠墙、朝最近敌人射击。明确其为手写基线。
- PPO：使用相同观测、动作和测试条件。
- 训练种子 0/1/2；验证种子 1000–1009；最终测试种子 2000–2029，分离用途。
- 初次工程验证可只训练 seed=0，报告必须注明；简历中的泛化/稳定性结论需要补足至少 3 个训练种子。
- 逐局输出 seed、策略/模型哈希、结果、存活秒数、生命损失、击杀、总奖励、墙体接触/卡住候选事件、耗时和异常。
- 失败轨迹记录动作及关键状态摘要，能按同 seed/动作重新跑；复现偏差单独报告。卡住只是启发式标记，未确认不能称为发现游戏 Bug。

## 实现顺序与验收

1. 固定原游戏和上游插件版本；原游戏无脚本错误运行，记录资源来源。复制时保留第三方许可证，不能把原素材宣称为新项目原创或随意改许可证。
2. 接管输入、固定步进、种子和回合重置。通过 100 局自动 reset；断言无上一局节点残留、动作映射正确、奖励不重复、终止状态正确。
3. 打通 Python 与真实 Godot，运行随机与规则基线。通过 Gymnasium 检查、异常连接退出和同 seed/动作重放测试。
4. 完成短训、模型保存、加载推理。明确短训成功仅代表训练链路可用，不代表学会游戏。
5. 在冻结配置下训练并测试，输出三种策略对照和失败记录，不挑最好的单局录像代替评测。
6. 整理 README、一键启动/训练/评测脚本、演示录像、架构图、来源说明和可准确使用的简历条目。

首个可交付里程碑是步骤 1–3 的真实游戏闭环；后续训练质量由实验决定。代码可先本地验收，新项目公开发布前另检查素材授权范围。
