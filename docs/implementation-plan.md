# 实施计划与责任边界

设计已由用户确认。依次完成：

1. 获取原游戏 `1ce73ad`、插件 `998c357`，保留来源，建立独立目录与 Python 3.12 环境。
2. 原 Player 增加 Agent 输入；原游戏固定物理计时、可指定刷新/掉落随机种子；保留人工模式。
3. 基于上游 AIController2D 和 GodotEnv，增加明确 reset/seed/末状态语义的 Session/Gymnasium 适配器。
4. 以真实 Godot 进程验证 100 次 reset、相同 seed 与动作重放、动作推进帧数、奖励与终止、断连退出。
5. 冻结随机与规则基线。运行 10,000 步简单课程短训，随后 100,000 步原游戏训练；保存模型、配置和验证记录。
6. 测试种子 2000–2029 固定对照，导出逐局 JSON、动作轨迹、HTML；不得用测试结果挑模型。
7. 完成启动脚本、来源说明、限制、运行报告与演示入口。新项目本轮不公开发布。

上游算法归属 Stable-Baselines3；上游控制器归属 Godot RL Agents。新增工作是原游戏适配、协议可靠性、观测、奖励、回合语义、基线、评测与重放。没有重新实现 PPO，也没有训练大模型。

## 与初始设计的具体落实

- 原仓库插件的旧子模块没有直接使用；选用已阅读的当前协议 0.7 插件。
- Python 使用 PyPI godot-rl 0.8.1，其源码与 GitHub main 有差异，因此明确覆盖 reset、step、消息读取、进程生命周期，不直接套用其 SB3 VecEnv。
- 保留原游戏引擎战斗实现，训练模式将敌人死亡动画的结算延迟按原帧时长换算成物理计时，以避免显示帧率影响爆炸/掉落时机。不是新建 Python 战斗模拟器。
- 每个训练进程仅一个游戏实例；通信只绑定 127.0.0.1。训练版结果不暂停整棵场景树，末状态返回后由调用方明确 reset。
- 环境使用结构化特征，不属于视觉 Agent。射击和移动使用九方向离散动作；原游戏的 Buff 仍然能改变实际射击模式。
